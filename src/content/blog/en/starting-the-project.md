## A starting point, and a set of questions

I want to understand what it takes to move from an engine drawing to a model that can be examined, questioned, and eventually compared with physical work. This notebook will follow that process in small steps: interpreting source material, reconstructing geometry, studying individual problems, and documenting what each new piece of evidence changes.

The KJ66 is the starting point named in this project. That gives the investigation a useful boundary and a consistent vocabulary. It does not establish the condition of any drawing, the accuracy of a reconstruction, or the performance of a future engine. Those questions will need their own evidence as the project develops.

This first edition sets out the work I intend to do. The images are original conceptual schematics, and these opening articles describe investigations that remain to be carried out.

## How I plan to approach it

The first task will be to assemble a source inventory. A drawing, a written note, and an interpreted feature in CAD should remain distinguishable. For each feature, I want to record where the information came from and what was added to make the reconstruction possible.

From there, I plan to build a model in manageable sections and record the interfaces between them. A model that looks complete can still contain unanswered questions. I want those questions to remain visible alongside the images, so a future revision can explain both its purpose and the assumptions it changes.

Analysis, manufacturing, and testing are later parts of the intended journey. Each will need a clearly described configuration. A result should belong to the model or physical setup that produced it, with enough context to make a comparison useful.

## Reading the first illustration

The overview above is a visual introduction to the notebook. The numbered callouts identify a front assembly, an internal layout, and an outlet. The cutaway-like opening makes the composition easier to read; it is an illustration choice rather than a section exported from a project model.

There are deliberately no dimensions or performance values on the image. It should help readers orient themselves while making no claim about a finished reconstruction. When real model images become available, their captions will identify the revision and explain what the view actually shows.

## Questions I want to keep open

Which source material can be used and shared? Which features are stated clearly, and which require interpretation? What should be reconstructed first to make later interface decisions easier to review?

I also want to establish how revisions will be named and how an unresolved detail will be carried forward. These sound like publishing questions, but they affect the engineering story: without that record, a polished image can conceal why a change was made.

## What a future update needs

A useful next article will include a real source inventory, a specific reconstruction question, and images of the work performed. It should show the proposed change and explain how it was checked within a stated scope. Anything still unresolved should remain part of the conclusion.

The next planned investigation is [reconstructing the engine from scanned drawings](../reconstructing-from-drawings/). This notebook will grow through those individual questions, with downloadable files introduced when actual revision packages are ready.
